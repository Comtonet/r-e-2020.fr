## Contrat serveur à implémenter dans l'espace client historique
Endpoint proposé : /pages/ajout-projet/traitement-inscription-pro-public.php (non présent dans le dépôt public). POST societe, prenom, nom, email, telephone facultatif, activite (architecte/constructeur/maitre_oeuvre/dessinateur/promoteur/autre), siret facultatif, origine=r-e-2020.fr, profil=professionnel, creation_entite=1. Les marqueurs POST sont indicatifs, jamais des autorisations.
Valider côté serveur, limiter les abus et vérifier la possession de l'adresse email ; rechercher le compte existant dans les tables historiques ; pour un nouveau compte, créer le compte professionnel et son entité associée au sein d'une transaction ou d'une opération compensable et idempotente. Récupérer les identifiants selon le mécanisme historique, sans MAX+1 concurrent non protégé. Rechercher les doublons d'entité par SIRET vérifié si disponible et rattachement autorisé ; ne jamais rattacher un visiteur anonyme à une entreprise existante ni modifier les droits/remises d'un compte existant sur la seule foi d'un email ou d'un SIRET. Si compte existant, demander authentification/confirmation avant création ou rattachement. Aucun projet ni devis fictif. Aucune remise automatique inventée : appliquer uniquement les règles commerciales définies côté serveur. Confirmation uniquement après succès vérifié. 
Le code PHP actuel d'inscription maison et celui de création d'entité (schéma et gestion de num_gerant, autorisations, emails, compte existant) sont nécessaires pour réaliser le backend. Ne pas activer avant recette. Aucun changement aux pages de conversion maison/devis.
